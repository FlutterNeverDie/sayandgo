큐플레이스 (Q Place) 설계안

소상공인 익명 질문 · 피드백 웹 서비스 / React + Firebase / 2026-11-19 v3
에스크 같은 "링크로 익명 질문 받기" 흐름을 매장용으로 옮긴 서비스.

최신 문서: 데이터 구조 · 보안 규칙의 최종본과 신고 · 차단 · 약관은 safety-and-policy.html, 구성도 · 플로우는 diagrams.html. 이 문서 4장의 규칙은 초안입니다.
v3에서 바뀐 것
  • ID 입력 제거. 가입은 이메일 · 비밀번호 · 상호명(storeName) 세 칸만 받습니다.
  • 가게 링크는 가입할 때 자동으로 생성되는 짧은 코드입니다: qplace.xx/q/k7m2xp9a
  • 질문은 10개씩 불러오고 캐싱을 넣어 읽기 횟수를 줄입니다.
  • 그대로 유지: Cloud Functions 없음, 이메일 인증 후 사용, 단순 금칙어, 에스크는 흐름만 참고하고 이름 · 디자인은 따로.

00한눈에 보기

  • 착수 순서: 뼈대 + 에뮬레이터 → 가입 · 이메일 인증 · 로그인 → 손님 질문 페이지 → 받은 질문함 → 링크 · QR → 설정 · 비밀번호 재설정 → 다국어 · 다듬기 → CloudFront 배포.
  • Firebase 구성: Auth(이메일/비밀번호) + Firestore + 보안 규칙. Storage · Functions는 쓰지 않습니다.
  • 비용: 인증 · 재설정 메일은 무료. 처음엔 무료 요금제로 시작하고, 트래픽이 늘면 종량제로 바꿔도 광고 수익으로 충분히 감당됩니다(10장 참고).

03가입 · 로그인

가입 시 받는 값

필드규칙UX
이메일형식 검사"로그인과 비밀번호 찾기에 써요. 손님에게는 보이지 않아요."
비밀번호8자 이상, 영문 + 숫자 필수, 특수문자 권장(필수 아님)대문자 · 특수문자 강제 없음. 강도 표시 + 보기/숨기기 토글, 확인 입력란 없음.
상호명 storeName1~30자, 앞뒤 공백 제거, 금칙어 검사. 중복 허용(같은 이름의 가게가 여러 곳 있을 수 있으므로)."손님 화면에 보이는 이름이에요". 설정에서 언제든 변경 가능, 바꿔도 링크는 그대로.

가게 링크 (자동 생성)

  • 가입할 때 8자리 랜덤 코드를 만들어 그대로 가게 문서 ID로 씁니다. 예: /q/k7m2xp9a
  • 글자는 헷갈리는 문자(0 · o · 1 · l · i)를 뺀 영문 소문자 + 숫자 31종만 씁니다. 손님이 링크를 손으로 옮겨 적어도 틀리지 않게.
  • 경우의 수가 약 8,500억이라 겹칠 일은 거의 없고, 혹시 겹치면 보안 규칙이 막으니 새 코드로 한 번 더 시도합니다.
  • 상호명을 링크에 넣지 않는 이유: 한글이 URL에 들어가면 QR이 훨씬 촘촘해지고, 이름을 바꾸면 링크도 바뀌어야 하기 때문입니다. 짧은 코드는 QR이 성기고 작게 출력해도 잘 찍힙니다.
  • 링크는 영구 고정입니다. 변경 기능은 넣지 않습니다(매장에 붙은 QR이 깨지므로).

가입 흐름

  1. 입력 검사 → createUserWithEmailAndPassword(email, pw). 이미 가입된 이메일이면 여기서 안내.
  2. 코드 생성 → 같은 배치로 users/{uid}와 stores/{code}(상태 pending) 생성. 규칙이 "코드 문서가 없을 때만, 계정당 가게 하나만" 허용.
  3. sendEmailVerification() → /verify: "메일함(스팸함 포함)에서 인증 링크를 눌러 주세요", 다시 보내기(60초 간격).
  4. 인증 후 돌아오면 토큰을 새로 받고 가게를 active로 → 받은 질문함으로 이동, 상단에 내 링크와 "QR 받기" 버튼.

로그인 · 비밀번호 재설정

  • 로그인: 이메일 + 비밀번호. 인증 전이면 /verify로.
  • 재설정: /reset에서 이메일 입력 → sendPasswordResetEmail. 가입 여부와 상관없이 같은 문구로 응답.
  • 메일 언어: auth.languageCode를 화면 언어로 맞추면 Firebase가 그 언어 템플릿으로 보냅니다.
  • 메일 링크는 처음엔 Firebase 기본 처리 페이지, 다듬기 단계에서 자체 화면 /auth/action으로 교체.

04Firestore 데이터 구조

경로읽기쓰기내용
stores/{code}누구나가입 때 생성, 이후 주인만 상호명 · 상태 변경가게 공개 정보. 문서 ID = 링크 코드
stores/{code}/questions/{qid}누구나 (미답변 포함)생성은 누구나(규칙 검사), 답변 · 삭제는 주인질문 + 답변을 한 문서에
users/{uid}본인만가입 때 생성내 가게 코드, 화면 언어
// stores/k7m2xp9a
{
  storeName: "연남동 로스터리",
  ownerUid: "Xk3f...",
  lang: "ko",
  status: "active",           // "pending"(인증 전) | "active" | "deleted"
  createdAt: Timestamp
}

// stores/k7m2xp9a/questions/{auto-id}
{
  body: "디카페인 원두도 따로 파시나요?",
  lang: "ko",
  status: "open",             // "open" | "answered"
  answer: null,               // 또는 { body: "네, 200g 단위로 팝니다.", at: Timestamp }
  createdAt: Timestamp
}

// users/{uid}
{ storeCode: "k7m2xp9a", uiLang: "ko", createdAt: Timestamp }

질문 문서에는 작성자를 알 수 있는 값을 넣지 않습니다. 손님은 로그인하지 않습니다.

인덱스

  • 손님 화면: createdAt desc 10개씩 (기본 인덱스)
  • 사장님 "새 질문" 탭: status == "open" + createdAt desc (복합 인덱스 1개)

보안 규칙

rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    function signedIn()  { return request.auth != null; }
    function verified()  { return signedIn() && request.auth.token.email_verified == true; }
    function data()      { return request.resource.data; }
    function storeDoc(c) { return get(/databases/$(db)/documents/stores/$(c)).data; }
    function isOwner(c)  { return verified() && storeDoc(c).ownerUid == request.auth.uid; }
    function onlyChanges(keys) {
      return request.resource.data.diff(resource.data).affectedKeys().hasOnly(keys);
    }
    function validName(n) { return n is string && n.size() >= 1 && n.size() <= 30; }

    match /users/{uid} {
      allow read: if signedIn() && request.auth.uid == uid;
      allow create: if signedIn() && request.auth.uid == uid
        && data().keys().hasOnly(['storeCode','uiLang','createdAt'])
        && data().createdAt == request.time
        && getAfter(/databases/$(db)/documents/stores/$(data().storeCode)).data.ownerUid == uid;
      allow update: if signedIn() && request.auth.uid == uid && onlyChanges(['uiLang']);
    }

    match /stores/{code} {
      allow read: if true;
      // 문서가 없을 때만 create가 적용되므로 코드 중복은 여기서 막힘
      allow create: if signedIn()
        && code.matches('^[23456789abcdefghjkmnpqrstuvwxyz]{8}$')
        && data().keys().hasOnly(['storeName','ownerUid','lang','status','createdAt'])
        && data().ownerUid == request.auth.uid
        && data().status == 'pending'
        && data().createdAt == request.time
        && validName(data().storeName)
        && !exists(/databases/$(db)/documents/users/$(request.auth.uid))          // 계정당 가게 1개
        && getAfter(/databases/$(db)/documents/users/$(request.auth.uid)).data.storeCode == code;
      allow update: if isOwner(code) && onlyChanges(['storeName','lang','status'])
        && validName(data().storeName)
        && (data().status == resource.data.status
            || (resource.data.status == 'pending' && data().status == 'active')
            || (resource.data.status == 'active'  && data().status == 'deleted'));
      allow delete: if false;   // 탈퇴해도 코드 재사용 금지

      match /questions/{qid} {
        allow read: if true;
        allow create: if storeDoc(code).status == 'active'
          && data().keys().hasOnly(['body','lang','status','answer','createdAt'])
          && data().keys().hasAll(['body','lang','status','answer','createdAt'])
          && data().body is string && data().body.size() >= 2 && data().body.size() <= 500
          && data().lang is string && data().lang.size() <= 10
          && data().status == 'open' && data().answer == null
          && data().createdAt == request.time;
        allow update: if isOwner(code) && onlyChanges(['answer','status']);
        allow delete: if isOwner(code);
      }
    }

    match /{document=**} { allow read, write: if false; }
  }
}

규칙 테스트(@firebase/rules-unit-testing): 남의 질문 삭제, 질문 본문 수정, 인증 전 계정의 답변, 같은 코드 두 번 생성, 계정 하나로 가게 두 개 만들기, 준비 중 가게에 질문 등록이 모두 막히는지.

탈퇴: 앱에서 질문을 나눠 전부 삭제 → 가게 deleted → users 문서 삭제 → Auth 계정 삭제(비밀번호 한 번 더 입력). 코드는 재사용하지 않아 매장에 남은 QR이 다른 가게로 연결되지 않습니다.

05읽기 줄이기 · 캐싱

화면불러오는 방식읽기 수
손님 가게 페이지가게 문서 1개 + 질문 10개를 한 번만 가져옴(getDocs, 실시간 구독 안 함). "더 보기"를 누를 때만 다음 10개.첫 방문 약 11회
손님이 질문 보냄목록을 다시 불러오지 않고 보낸 질문을 화면 맨 위에 바로 끼워 넣음추가 0회 (쓰기 1회)
사장님 받은 질문함최근 10개를 실시간 구독(onSnapshot). 처음 이후에는 바뀐 문서만 과금됩니다.첫 10회 + 새 질문당 1회

캐시 3단

  1. Firestore 로컬 캐시 (persistentLocalCache + 여러 탭 지원): 기기에 저장해 두고, 다시 열면 캐시를 먼저 보여 줍니다.
  2. 화면 단 캐시 (TanStack Query, 손님 화면 staleTime 60초): 1분 안에 같은 가게 페이지를 다시 열거나 뒤로 가기 하면 서버를 안 거칩니다. 아래로 당겨서 새로고침하면 바로 다시 가져옵니다.
  3. 가게 문서(상호명)는 거의 안 바뀌므로 staleTime 10분.

개수 표시(예: "새 질문 4")는 count() 집계 쿼리를 따로 날리지 않고, 이미 불러온 목록으로 계산합니다.

06금칙어 (단순 비교)

// web/src/lib/bannedWords.ts
export const BANNED_WORDS: Record<string, string[]> = {
  ko: ['…', '…', '…'],   // 나라별 대표 욕설 · 비방 몇 개씩
  en: ['…', '…'],
  ja: ['…', '…'],
  zh: ['…', '…'],
  es: ['…', '…'],
};

const ALL = Object.values(BANNED_WORDS).flat().map(w => w.toLowerCase());

export function hasBannedWord(text: string): boolean {
  const t = text.toLowerCase();
  return ALL.some(w => t.includes(w));
}
  • 화면 언어와 상관없이 모든 나라 목록을 한 번에 검사. 질문과 상호명에 적용, 사장님 답변에는 미적용.
  • 걸리면 "이 표현은 등록할 수 없어요"만 보여 주고 어떤 단어인지는 밝히지 않습니다.
  • 한국어는 "시발점" 같은 정상 단어가 걸리지 않게 단어를 고를 때 주의.

07다국어 (i18n)

  • react-i18next + i18next-browser-languagedetector. 감지 순서: 직접 고른 언어 → 브라우저 언어 → 영어.
  • 국가보다 브라우저 언어 우선(한국 매장의 일본인 관광객에겐 일본어 화면).

#FFF1B8 "답변 전"
  • 민트 버튼에는 흰 글자 대신 Ink 글자(밝은 민트 위 흰 글자는 대비 부족).
  • 따뜻한 종이색 바탕, 그림자 대신 1px 선, 모서리 8~10px. 한국어 Pretendard, 전표 번호 · 시간만 고정폭.
  • 하지 않을 것: 보라 · 파랑 그라데이션, 반짝이 · 로봇 아이콘, 유리 효과, 그라데이션 글자, 채팅 말풍선, "AI"라는 단어.
  • 모바일: 터치 영역 44px 이상, 주요 버튼 하단, iPhone 안전 영역, 키보드가 올라와도 보내기 버튼이 보이게.
  • 광고 자리는 처음부터 정해 둡니다: 손님 화면 질문 목록 중간(10개 단위 사이)과 맨 아래. 입력창 근처에는 두지 않습니다(잘못 누르기 쉬움).

10비용과 광고 수익

Firestore 종량제 단가는 읽기 10만 건당 몇 센트 수준입니다. 손님 페이지 한 번 여는 데 약 11회 읽기니까 10만 읽기 ≈ 페이지뷰 9,000회입니다.

페이지뷰 9,000회 기준대략
Firestore 읽기 비용몇 센트 (100원 안쪽)
CloudFront 전송 비용정적 파일이라 몇 센트 수준
애드센스 수익 (모바일, 페이지뷰 1,000회당 수백 원~수천 원 가정)수천 원~수만 원

수익 단가를 아주 낮게 잡아도 비용보다 수십 배 크므로 광고로 충분히 감당됩니다. 무료 한도(하루 읽기 5만 건 ≈ 페이지뷰 4,500회)를 넘기 시작할 때 종량제로 바꾸고, 예산 알림만 걸어 두면 됩니다.

애드센스 승인 주의:
  • 손님이 쓴 글이 바로 공개되는 페이지는 애드센스 정책상 사용자 콘텐츠 관리가 필요합니다. 금칙어 + 사장님 삭제 + 이용약관 · 신고 안내 문구가 있어야 승인에 유리합니다.
  • 내용이 거의 없는 페이지(질문 0개인 가게 등)만 많으면 "가치가 낮은 콘텐츠"로 거절될 수 있어, 소개 · 이용 방법 · 개인정보처리방침 · 이용약관 페이지를 같이 준비합니다.
  • 사장님 화면(받은 질문함)에는 광고를 넣지 않는 쪽을 추천합니다. 손님 화면에만.

11개발 순서

  1. 뼈대 + 에뮬레이터 첫 스텝
    Vite + React + TS, Firestore · Auth 에뮬레이터, 라우터, TanStack Query, i18n(ko/en), 디자인 토큰, 검증 함수 · 코드 생성 단위 테스트, 보안 규칙 초안과 규칙 테스트.
  2. 가입 · 이메일 인증 · 로그인
    가입 배치 쓰기(링크 코드 생성), 인증 메일 · 대기 화면, 로그인, 인증 완료 화면 보호.
  3. 손님 질문 페이지
    /q/:code, 금칙어, 질문 등록, 10개씩 더 보기, 캐시, 30초 잠금.
  4. 받은 질문함
    탭, 답변 쓰기 · 수정, 삭제, 여러 개 선택 삭제, 실시간 갱신.
  5. 링크 · QR
    복사, 공유, QR PNG 저장.
  6. 설정 · 비밀번호 재설정
    재설정 메일, 비밀번호 변경, 상호명 변경, 탈퇴.
  7. 다국어 · 다듬기
    ja 추가, 금칙어 목록 채우기, /auth/action 자체 화면, 소개 · 약관 · 개인정보처리방침 페이지, 실제 휴대폰 테스트.
  8. 실서버 연결
    Firebase 프로젝트(리전 지정), 규칙 · 인덱스 배포, App Check, 메일 템플릿 · 발신 도메인.
  9. AWS CloudFront 배포
    S3 + CloudFront, SPA 라우팅(403/404 → /index.html), 도메인 · 인증서, Firebase Auth 승인 도메인 추가.
  10. 애드센스
    도메인 연결 · 콘텐츠가 어느 정도 쌓인 뒤 신청, 승인 후 광고 자리 활성화.

첫 스텝에서 할 일

# 0. Firebase CLI 업데이트 (현재 13.35)
npm i -g firebase-tools@latest
firebase login

# 1. 웹앱
npm create vite@latest web -- --template react-ts
cd web && npm i firebase react-router-dom @tanstack/react-query \
  i18next react-i18next i18next-browser-languagedetector qrcode

# 2. Firebase
firebase init firestore emulators     # 에뮬레이터: auth, firestore, UI

# 3. 실행
firebase emulators:start      # 에뮬레이터 UI http://localhost:4000 (인증 메일 링크도 여기서 확인)
npm --prefix web run dev      # 웹 http://localhost:5173

12미리 짚어 둘 위험

  • 도배 · 봇: 서버가 없어 IP 기준 제한은 못 합니다. 30초 잠금 + App Check + 여러 개 선택 삭제로 대응.
  • 미답변 질문 즉시 공개: 단어 목록을 피한 비방이 사장님보다 손님에게 먼저 보일 수 있습니다. 나중에 "확인한 질문만 공개" 설정을 넣을 여지를 둡니다.
  • 금칙어 우회: 앱 화면에서만 검사하므로 API 직접 호출로 피할 수 있습니다. 필요하면 같은 단어를 보안 규칙 정규식에도 추가.
  • 인증 메일 스팸함: /verify에 "스팸함도 확인해 주세요" 안내, 도메인 확정 후 발신 주소 변경.
  • CloudFront + Firebase Auth: 배포 도메인을 Auth 승인 도메인에 넣지 않으면 로그인 실패.
